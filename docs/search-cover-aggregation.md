# 搜索页：封面指纹聚合 + 结果筛选（2026-11-15）

**状态**：线上 `tv.ycxdev.com` 已部署 `0fecf87`；CI `43660863805` / deploy `43660924771`。
**适用**：改搜索页聚合、筛选、封面取图前先读；搜索页 UI 验证见 [ui-verification.md](./ui-verification.md)，全局交接见 `docs/tv-handover-2026-11-15.md` §8。

## 0. 一句话结论

搜索结果用**两层身份**聚合：先按**封面视觉指纹（dHash）**认「同一张图」，再按**片名 + 年份**兜一层
（同名同年即使海报不同也并进一张卡）；筛选条从聚合组自动生成。

**2026-11-16 口径变更**：同名同龄不再拆开。用户明确要求「同一部片就并到一起，剧版和电影版并一张卡也不影响」。
原来「同名同年但海报不同就拆开」的做法已废弃，原因与代价见 §10。

**仍然不要做的事**：不要把 dHash 全局阈值调高来追求「同片不同海报」——实测 21 张真实海报两两距离中位数
**32**、最小 24，和「不相干的两部片」完全重叠，阈值提到 24+ 会随机并错片（§10 有分布数据）。

## 1. 背景与旧行为

旧版只按「片名 + 年份」分桶：

- 「色戒」搜索里，同一部片被源站写成不同片名/年份时会拆成多张重复卡；
- 同名同年的不同影片又会被并成一张「N 源」卡，封面只代表其中一部，点封面可能播到另一部；
- 结果卡上的类型/年份/18禁只是标签，不能筛选。

线上真实「色戒」数据（默认源，`filterAdult=false`，2026-11-15）：

| 口径 | 聚合组 |
|---|---|
| 旧版片名 + 年份 | 27 组 |
| 封面视觉指纹（当前） | 19 组（本地 60 条样本） |
| 再加片名 + 年份全局并集（未采用） | 17 组 |

## 2. 视觉指纹：算法与分组

### 2.1 dHash

代码：`src/lib/cover-visual-hash.ts`。

- 先按 **4:5**（宽/高）**中心裁切**（`coverCropRect`），再**两段缩放**到 **9×8** canvas、按 BT.601 转灰度；
- 每行比较相邻像素灰度，左暗记 1，得到 **64 bit / 16 位十六进制**；
- 两个指纹的汉明距离 ≤ **10** 视为同一张封面，并查集聚类；
- 簇代表取簇内**字典序最小**的指纹，保证流式追加时 group key 稳定。

两段缩放是 2026-11-15 补的：把 540×770 这类大图**一步** `drawImage` 到 9×8，浏览器走快速滤波，
压缩噪声会变成锯齿——同一张海报的两个扫描件实测差 **15** 位（阈值 10），被拆成两张卡。
先缩到 45×40 再缩到 9×8 后同一对只差 **1** 位，不同海报仍在 29–36。

裁切是 2026-11-15 补的：只拉伸整图会把「画幅差异」算成视觉差异。同一张主视觉，
采集站常见 2:3 海报和 9:16（顶部台标条 + 底部赞助/扫码区）两种裁切，整图 dHash
距离 19–21、超过阈值 10，于是「后会友期」被拆成 9 源 + 2 源两张卡（卡片显示又是
`aspect-[2/3] + object-cover`，两卡看起来一模一样）。裁成 4:5 后同一对距离降到 **4**。

实测距离（同图/不同图的分界）：

| 对比 | 距离 |
|---|---|
| Samsara 270×371 vs 350×477（同海报不同分辨率） | 7 |
| 同一张绿海报的两个扫描件（线上「废柴」vs 12 源卡，540×770 / 650×928） | 15（一步）/ **1**（两段） |
| 《色，戒》绿海报 vs 美版海报（同片不同设计） | 35 |
| 《三生三世十里桃花》剧版海报 vs 影版海报 | 28 |
| 「后会友期」2:3 海报 vs 9:16 同主视觉（整图拉伸 / 裁 4:5） | 21 / **4** |

阈值取 10 是**精度优先**：宁可把同一张海报的不同扫描件拆开，也不把不同影片并在一起。想提高召回时先看 §8。

### 2.2 分组键

代码：`src/lib/search-groups.ts`（并查集）。

每个条目先算一个 primary 键，优先级：

1. `visual:<簇代表>`：有视觉指纹；
2. `cover:<URL 指纹>`：有 `pic` 但没算到视觉指纹（超出 120 张预算 / 地址无法解析 / 取图失败）时，按 URL 指纹；
3. `title:<归一化片名>|<年份>`：连 URL 指纹都拿不到时，退回旧口径。

然后把 primary 键和 `title:<归一化片名>|<年份>` 键 **union** 起来（2026-11-16 新增）：
**同名同年 → 同一组**，不管封面是否相同、是否算到指纹。跨年不并（《色戒》2002 vs 2007 是两部片）。
并查集的根取**先出现**的键，保证流式追加时已有分组的 key 不跳变（key 变了 React 会整卡重挂载）。

**没给 `pic` 的条目不再展示**（见 §2.3）：它们只会落在 `title:` 兜底桶里，单独成一张胶片占位卡。

取图失败（有 `pic` 但拿不到像素）的条目**照常展示**，走 URL/片名兜底（2026-11-16 改）：代理取不到图 ≠ 浏览器显示不出来（很多图床直连正常、Worker 出网 525）。

前缀还会带 `f:`（正片）/`c:`（解说），所以「电影解说/影视解说」不会并进正片来源；它们常直接复用影片海报，不隔离会污染正片来源列表和封面直达播放。这个前缀在 primary 键和 title 键上都带，两层身份都不会跨变体并组。

### 2.3 等待与兜底

- 指纹还没算完的条目**暂不参与聚合**，避免先按片名分组、随后又跳变；
- **没有封面的条目直接隐藏**（2026-11-15 二轮收敛；2026-11-16 收窄为只隐藏「源站没给 `pic`」），分两层：
  1. **数据层**（`src/app/page.tsx` 的 `visibleList`）：只过滤掉没有 `pic` 的条目——没有指纹也渲染不出封面，退回 `title:` 兜底只会单独成一张占位卡。
     **取图/解码失败（`coverHashes.isFailed`）不再在这里隐藏**：代理失败常常只是 Worker 出网问题，隐藏等于吞掉真实来源。
  2. **显示层**（`AggregatedCard` 的 `onCoverBroken`）：`pic` 存在但浏览器加载不出来（图床不可达/防盗链/混合内容）时，
     先换组内下一张封面；全失败才把整组隐藏（会话级，刷新重试；换关键词清空）。多源组不会因为第一张封面挂了就整组消失。
- 结果头「N 部 · M 条」的**条数从聚合组统计**，已隐藏的来源不再计数。
- 有 `pic` 但没进指纹预算（见 §4.4）的条目：URL 指纹 → 片名 + 年份兜底，**正常展示**（有封面图可看）；
- 单次搜索最多算 **120 张**，而且预算**只花在没缓存的封面**上（已缓存的不占名额）。否则同一关键词反复搜索永远只算同一批，
  尾部封面永远拿不到指纹——线上「庆余年」179 条结果里 60% 被拆卡就是这个原因（见 §9）。

### 2.4 组标题

`groupName()` 不按出处数量直接取多数，而是优先「更干净」的写法：

- 不带 4 位年份：`色戒` 优先于 `色戒2007`；
- 不带括号附注：`色戒` 优先于 `色戒[电影解说]`；
- 其次更短、再其次出处更多。

## 3. 筛选条

代码：`src/lib/search-facets.ts`；UI 在 `src/app/page.tsx`。

- 搜索框正下方三行 chip：**类型 / 年份 / 分级（18禁）**；
- 按**聚合组**计数，和卡片标签一致：组内 5 个「剧情片」来源只算 1 部；
- 同类目多选 OR、跨类目 AND；
- 计数跟随**其他类目**的当前选择（选了「伦理片」，年份只统计伦理片；本类目的选择不参与自己的计数，方便改选）；
- 已选但当前结果不存在的值保留为 0，避免「筛选还在生效但标签消失」；
- 关键词变化清空筛选；筛选变化重置分页与冻结顺序；
- 窄屏横向滚动、`sm` 以上换行；「清除筛选」在结果计数下方；无结果显示空态 + 清除按钮。

## 4. 取图链路与线上坑（重要）

### 4.1 为什么需要代理

浏览器直连图床时 canvas 会被跨域污染，`getImageData` 读不到像素；必须把图取回同源（或拿到 CORS 许可）才能算 dHash。

### 4.2 实际链路

`src/components/use-cover-hashes.ts`：

1. **先试浏览器 CORS 直连** `fetch(url, { mode:'cors', credentials:'omit', referrerPolicy:'no-referrer' })`；
   - 成功 → 直接用 blob 算 dHash；
   - 失败/非 2xx/拿到防盗链 HTML（`blob.type` 非 `image/*` 或解码失败）→ 走同源代理；
   - 按 host 记住 `cors` / `proxy` 结论，避免同一图床每个封面都先失败一次。
2. 同源 `GET /api/cover?url=`：
   - 需登录（`guardRequest`），SSRF 校验（逐跳重定向也校验）；
   - 仅图片、≤3MB、拒绝 SVG、`Cache-Control: private, max-age=604800, immutable`、`nosniff` + CSP sandbox；
   - **HTTPS 返回 525/526（源站 TLS 握手失败）时降级 HTTP 重试**；
   - 浏览器私有缓存 7 天；dHash 另外存 localStorage。

### 4.3 线上踩过的坑

- **Cloudflare Workers 出网对部分图床返回 525**（TLS 握手失败），但同一路径 HTTP/浏览器直连正常；
  - 例：`hhmage.com` / `p.lztutu.com` / `p.bfp261112.com` 直连可用；`fffgood.com` / `mdzypic.com` / `dytt` HTTPS 525、HTTP 200。
- 只加 HTTP 降级还不够：`fffgood`、`mdzypic` 这类 host 浏览器 CORS 失败，必须走代理；`hhmage` 这类代理 525，必须走直连。两条路径缺一不可。
- 直连可能返回 **200 的防盗链 HTML**：必须校验 `blob.type` 并 `try/catch` 解码，失败后回退代理；否则该封面会永久停在 URL 兜底。
- 本地 dev 的 `/api/cover` 会因 Clash fake-IP + SSRF 被拦；**不要用本地取图失败判断线上回归**。本地要验证视觉分组，用真实搜索结果 + 本地封面 mock，或直接对线上跑 shot。

### 4.4 成本/限额

| 项 | 值 | 说明 |
|---|---|---|
| 单次最多算指纹 | 120 张**未缓存**的 | 预算只花在没缓存的封面上，已缓存的不占名额（否则尾部永远轮不到）；其余 URL/片名兜底 |
| 并发 | 8 | 120 张封面约几秒到十几秒算完，期间结果按批出现 |
| 失败熔断 | 连续 4 张失败 → **暂停 15s 后自动续跑** | 只暂停不判死：一次图床连败不该让剩下几十张封面失去指纹 |
| 取图失败 | 照常展示（URL/片名兜底） | 代理失败 ≠ 浏览器显示不出来；只有卡片 onCoverBroken 才隐藏整卡 |
| localStorage 哈希缓存 | 3000 条 **且** ≤1.2MB（LRU 双预算） | key `cover-visual-hashes-v3`；≈100 字节/条，600 条时代只有 60KB，条数才是瓶颈 |
| 代理响应缓存 | 浏览器私有 7 天 | 不占 Worker 的共享缓存 |
| 单张上限 | 3MB | 超限走兜底 |

线上「色戒」实测（旧 48 张预算时代）：71 条来源 → 46 张成功算完指纹；其余是 525/504 图床或阈值外，走 URL/片名兜底。
2026-11-16 把预算提到 120 后，「庆余年」123 张唯一封面全部进入队列（首搜），之后重复搜索命中缓存为 0 请求（见 §9）。

## 5. 关键决策记录

### 5.1 「同片名同年」全局并集：2026-11-15 否决，**2026-11-16 用户拍板启用**

> **现状（2026-11-16 起）**：同名同年**并组**（§2.2 的并查集）。下面保留的是当时的反例与顾虑，
> 供以后回看代价；用户在 2026-11-16 明确表示「剧版和电影版并到一张卡也不影响」，接受这个代价。
> 新的实现细节与实测见 §10。

2026-11-15 讨论过：视觉指纹会把同一部片的不同海报拆开（如《色，戒》2007 绿海报 13 源 + 美版 2 源），看起来像重复卡。

**收益**（色戒 60 条样本）：19 → 17 组，只少 2 张卡（15 源 + 9 源）。

**反例**（线上真实搜索「三生三世十里桃花」，46 条 / 0 失败）：

- 30 条片名完全一样、年份都是 **2017**；
- 同时包含 **电视剧版**（杨幂/赵又廷，类型 `国产剧/内地剧/大陆剧`）和 **电影版**（刘亦菲/杨洋，类型 `爱情片/爱情`）；
- 影版/剧版海报 dHash 距离 **28**；
- 片名 + 年份全局并集会把 30 条并成一张 30 源卡，播放/集数/备注全混。

类型标签也不能当保险：同一张封面 `8344128a...` 同时被源站标成 `国产剧` 和 `爱情片`。并查集还有传递闭包放大：片名年份连 A/B，视觉指纹连 B/C，会把 A/B/C 一起并掉。

**当时的结论**：不做全局并集，精度优先（宁多一张卡，不播错片）。**2026-11-16 用户改口径后按新结论执行。**

### 5.2 为什么阈值是 10，不是更高

- 10 能把 Samsara 的不同分辨率（7）合并；
- 「同海报不同扫描件」原先差 14 被拆开，根因是一步缩放产生锯齿；改两段缩放后同一对只差 1，
  不再需要靠调高阈值来兜；
- 16 仍低于三生三世剧/影（28），但需要更多 query 采样才能确认误并率；
- 更稳的做法是「同片名同年 + 指纹距离 11–16」近重复 tie-breaker，或详情演员/集数比对，而不是直接调高全局阈值。
- 2026-11-15 补了 4:5 取景 + 两段缩放后阈值仍是 10：同主视觉不同画幅 4、同海报不同扫描件 1、
  不同海报 27+，余量足够；没有调高阈值。
- 2026-11-16 用户要求「同片不同海报也并」时，阈值**仍然保持 10**：实测 21 张真实海报两两距离
  中位数 32、最小 24（§10），调到 24+ 会把不相干的影片随机并掉，调到 28 又刚好卡在三生三世剧/影。
  这条需求改用「片名 + 年份」层解决，见 §2.2 与 §10。

## 6. 已知边界

1. **同海报不同扫描件**：两段缩放后能合并（线上「废柴」1 源卡与 12 源绿海报卡差 1 位）；但如果是重新绘制的版本或不同裁切，仍可能超过阈值；
2. **没有封面的条目会被隐藏**（2026-11-15 决定，且不提示）：只隐藏**源站没给 `pic`** 的条目；取图失败不再隐藏（2026-11-16 改），
   `pic` 存在但浏览器显示不出来在显示层整卡隐藏（先换组内下一张封面）。失败状态是会话级缓存，刷新页面会重新取图；
3. **单次 120 张预算**；结果特别多时（唯一封面 >120）超出的封面不参与视觉合并（但仍按 URL 指纹展示，不会隐藏），
   下一次搜索会优先补算这些没缓存的封面（预算不再被已缓存的占住）；
4. **同一部片的不同海报设计**会分开（指纹优先的直接结果）；
5. **没有片名年份兜底硬并**：同名同年的剧/影不会误并，但同片不同海报也不会自动合并。
6. **首搜一个关键词会多拉封面原图**：120 张 × 平均 100–300KB，最坏十几 MB（仅首搜；之后走 `/api/cover` 7 天浏览器缓存）。
   移动流量敏感的话，后续可以在 `/api/cover` 加缩图参数（见 §7）。

## 7. 后续可选方案（按推荐顺序）

1. **按需合并 / 变体提示**：同名同年多组时显示「另有 N 种封面」，用户点开查看/手动合并，可拆分；零误合并、可逆。
2. **近重复 tie-breaker**：同片名同年 + 指纹距离 11–16 才合并；能收掉「废柴」这类，且三生三世（28）仍安全。需要更多样本验证误并率。
3. **详情比对**：只对歧义组取一条详情，比较演员/导演/集数；色戒 2007 演员相同可合，三生三世剧/影演员不同可分。代价是每组一次详情请求 + 匹配逻辑。
4. **外部 canonical ID**：豆瓣/Bangumi subject ID，解析到同一 subject 才合并；最准但最重，要处理接口稳定性/反爬。
5. **镜像/内容哈希去重**：同一 `78288c...` 文件名在多个图床出现时只算一次，可减少请求；不能解决不同文件名的情况。

## 9. 2026-11-16：指纹预算 48 → 120 + 只算未缓存 + 熔断改为暂停（A/B/C）

**触发**：用户搜「庆余年」反馈「按封面聚合没生效」。实测（登录态直打 `/api/search`）：

- 179 条结果 / **123 张唯一封面**；
- 按唯一封面序号分桶：1–48 → 71 条、49–96 → 77 条、97+ → 31 条 ⇒ **108 条（60%）没有指纹**；
- 首屏 24 张卡里 5 张封面不在指纹缓存里，正是拆卡的那几张：
  - 庆余年第一季特别版 ×3 张卡，dHash 两两距离 **0**（同一张图被拆 3 卡）；
  - 庆余年第一季特别篇 ↔ 庆余年 23 源大卡：**0**；
  - 庆余年第一季 特别版 ↔ 大卡：**1**；庆余年之风起沧州 ×2：**1**；庆余年之少年风流 ×2：**1**；
- 该拆没拆的也对得上：庆余年 23 源 ↔ 2 源距离 **33**、第二季 24 源 ↔ 2 源 **23**、第一季两卡 **38**
  （不同海报，§5.1 精度优先，拆开是对的）。

**根因**：`MAX_PER_SEARCH = 48`，且 `planned` 取的是「结果顺序前 48 张唯一封面」——**预算不滚动**。
同一关键词反复搜索永远只算同一批，尾部封面永远拿不到指纹；而 35 个源、150+ 条结果的搜索已经很常见。

**改动**（A/B/C）：

- A. `MAX_PER_SEARCH` 48 → **120**；`planned` 跳过已缓存封面（预算只花在没缓存的），并发 5 → 8。
  重复搜索会把预算滚到尾部未覆盖的封面。
- B. 熔断（连续 4 张失败）不再 `drainQueue()` 判死，改为**暂停 15s 后自动续跑**；
  `visibleList` 不再隐藏 `isFailed` 条目——代理取图失败 ≠ 浏览器显示不出来（很多图床直连正常、Worker 出网 525），
  是否真显示不了交给卡片的 `onCoverBroken`。
- C. 哈希缓存 600 条 → **3000 条 + 1.2MB 双预算 LRU**（`src/lib/cover-hash-cache.ts`，带单测）。
  说明：缓存是**客户端 localStorage**，一条 ≈100 字节，不是图片；localStorage 每源上限约 5MB，
  所以「20MB」在这里没有意义（≈20 万条），真要 MB 级存储得换 IndexedDB，而 dHash 只有 16 字符。

**代价**：首次搜索一个关键词最多多拉 ~120 张封面原图（最坏十几 MB、之后命中 `/api/cover` 7 天缓存）。

## 10. 2026-11-16：同名同年改为并组（用户改口径）

**用户原话**：「三生三世十里桃花这个例子不好，我还是坚持封面相同就聚合到一起，所以图片指纹距离可以再大些，
即时剧版和电影版集合到一起，也不影响的。」

**为什么不是「把 dHash 阈值调大」**：把线上 21 张真实海报两两比了一遍（`庆余年` 全部卡片 + 同页其他卡）：

| 统计 | 值 |
|---|---|
| 两两 dHash 距离 | 210 对，**中位数 32**、p25 29、p10 24、最小 0、最大 42 |
| ≤10（同一张图） | 5 对 |
| ≤14 | 8 对 |
| ≥23（不同图） | 196 对 |

也就是说「同一部片的两张不同海报」和「两部不相干的片」**完全落在同一区间**：阈值提到 24+
会把不相干影片随机并掉，提到 28 才够得到三生三世剧/影，而 28 与「不同图」的下界重叠。
所以阈值保持 10（同图 0–4、不同图 24+，余量最大），改由**片名 + 年份**这一层兜「同片不同海报」。

**实现**（`src/lib/search-groups.ts`）：

- 每个条目先算 primary 键（视觉指纹 → URL 指纹 → 片名+年份），再与 `title:<归一化片名>|<年份>`
  键做并查集 union；
- 同名同年 → 同一组（剧版/影版、不同海报、错配图都并）；跨年不并（《色戒》2002 vs 2007）；
- 解说（`c:`）与正片（`f:`）在两层键上都带前缀，不会互相并；
- 并查集根取**先出现**的键，流式追加时已有组的 key 不跳变。

**代价（用户已知并接受）**：同名同年的剧版/影版并成一张卡后，组内「年份/类型/集数」取多数，
来源列表里会同时出现剧和影的来源；从封面直达播放时可能播到另一个版本。要拆开只能靠视觉指纹
（同卡内不同封面），说明这类并组是有意为之。

**测试**：`src/lib/search-groups.test.ts` 新增/改写了 6 例——同名同年不同封面并组、同名不同年不并、
不同片名不并、剧/影距离 28 并组、有封面与无封面并组、无视觉指纹时按 URL 分组但仍按片名年份并组。
**线上验证**（部署后补）：`?s=三生三世十里桃花` 剧/影并成一张卡；`?s=庆余年` 大卡继续变大；
`?s=色戒` 2002 与 2007 仍分开。
